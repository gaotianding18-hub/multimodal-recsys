# 对照真实代码的学习入口

2026-10-12：教学从第5课继续。本文记录实现位置，不把工程完成记为用户已掌握。课程按docs/curriculum.md逐小节提问和练习，当前实验总览见docs/experiment_overview.md。

## 一次召回训练的数据流

scripts/prepare_hm.py以日期分组购买记录：一个用户在某天买过的商品集合是targets，严格早于当天的购买构成history。商品ID保留前导零。同一天没有可信先后顺序，不把当天目标提前放进输入。

recsys/hm_train.py的load把商品字符串映射为1…41585，0仅表示padding。histories形状[N,30]，每一行是一次训练查询；positives是长度不固定的商品ID列表。N=212658。验证/测试输入冻结在对应周开始，期间新增购买只作为目标。

recsys/clip_features.py从商品静态图文生成两组[N商品,512]浮点特征和[N商品,2]可用性标记。主干requires_grad_(False)，没有训练CLIP主干。item_ids必须与目录逐项相同，缺图不伪造，不删除目录商品。

recsys/hm_multimodal.py的items对实际所需ID去重后查特征：图像与文本分别投影512→64，门控根据投影和可用性输出两个权重。缺失分支权重为0。语义64维与可训练ID64维拼接为128维，再映射为归一化64维。只有文本的消融明确屏蔽图像；image分支缺图时回退文本，不能称完全纯图像实验。

users接收[B,30]的历史，编码为[B,30,64]，屏蔽padding、平均，再经过用户MLP得到[B,64]。商品候选表示[C,64]，矩阵点积生成[B,C]分数。用户编码不依赖当前候选，因而商品向量可以离线建索引。

candidate_masks把同batch所有basket正例和256随机商品合并去重，C随batch变化。positives[B,C]表示本日真实买过；allowed[B,C]把其他已知训练正例从负候选中屏蔽。未买过只是未观测，不是明确不喜欢。训练使用采样候选，评测使用全目录，两种口径必须区分。

advanced.py的contrastive_loss先除温度0.1，再在允许候选上计算log_softmax，对每行所有正例的负对数概率取平均。一个正例与多个正例都是合法目标。loss.backward计算梯度，AdamW更新融合/ID/用户塔；冻结的CLIP特征不回传到CLIP。

每轮evaluate用全部41585商品得分，取Top12，与目标集合计算Recall/NDCG/MAP；目标即使不在目录也保留为未命中。验证NDCG选择checkpoint，测试只评估选中权重。当前测试已探索性查看，不能称盲测。

## 排序和服务

hm_hybrid.py把模型Top100、历史最多30、固定近期热门100合并去重。hm_rank.py的Ranker引用advanced.InterestRanker，让候选与每个历史商品交互后形成候选相关兴趣。它输出偏好logit，不是CTR或购买概率。

最新hybrid排序把总体训练热度输入置0，只用历史是否出现、出现次数等因果特征。历史非本日目标或均匀非目标用于pairwise训练，仍有假负例风险。候选覆盖率提高并不保证Top12指标提高，当前真实实验已经出现这种失败。

hm_serve.py加载权重、校验索引、处理字符串历史、执行候选和排序，或使用强复购基线。图片仅从白名单商品路径读取。默认基线优于当前实验模型，因此演示明确给出方法选择，不用复杂模型名称掩盖差结果。

最终用户需要能独立解释上述形状、损失、负采样和限制，并亲自修改与复现实验，才能把对应能力作为自己的面试证据。
