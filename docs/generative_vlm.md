# 生成式商品视觉语言模型扩展（本机实验已完成）

业务问题：从商品图片生成结构化类别和颜色，研究生成式微调与推理效率。输出JSON，不生成用户行为、材质或偏好理由。已有推荐系统独立运行，属性接入前需验证可靠性。

候选模型HuggingFaceTB/SmolVLM-500M-Instruct，revision a7da5b986cb59b408707209984f360a5f4ad7e47，模型卡Apache-2.0；官方GitHub smollm公开说明支持Idefics3和微调。HF官方直连超时，使用公开hf-mirror下载，固定revision，未上传本地数据。model.safetensors官方LFS SHA256 d05b567eeaf534e83d375551f068ed57b5f52d37c657197f644af5ef9db091a2，大小1,015,025,832字节，下载完成后已核验通过，见reports/smolvlm_source_audit.json。

数据：现有590件商品，沿用图文匹配分组413/93/84。类别和颜色来自官方目录，是弱视觉监督；细颜色和商品类型可能视觉歧义。仅输入图片和固定指令，不把元数据答案放入输入问题。验证/测试保留，未知类别记录为泛化难点，不删去困难样本。

阶段验收：先batch1 Float32 MPS验证有限损失、答案token掩码、真实LoRA梯度/更新和生成推理；再固定训练预算并比较基线/微调后。正式结果按验证选权重，不按测试挑选。使用相同提示、图像预处理、解码和候选定义。评测JSON有效率、类别/颜色/联合元数据一致率、宏平均召回，附失败样本，不能称人工视觉准确率或业务收益。

效率改进需在可行性通过后预声明：对比图像切片、视觉token压缩及完整输入，在相同任务评测质量、内存和延迟。缩短token序列不自动意味着真实加速，不提前宣称原创剪枝或性能收益。用户后续需参与假设与代码学习。

## 效率实验预声明（在运行前记录）

scripts/benchmark_vlm_tokens.py：固定seed42验证选择的适配器，93件验证商品，原始64个连接器视觉token与uniform32/norm32/uniform16对比。uniform使用等间距索引，norm使用连接器输出L2范数排序且恢复空间顺序；均为简单已有基线，不是原创研究结论。保持单图512输入，先运行完整视觉编码器，再减少送入语言模型的视觉向量与对应占位token。不能声称视觉编码器加速。

统计元数据一致率、格式、p50/p95与结束MPS内存；计时包括视觉编码与生成，排除读图和预处理。一次固定顺序运行，输出长度、缓存和系统负载均可能影响速度；若有候选改善需之后随机顺序重复、固定生成长度测试和独立留出确认。不能根据本轮测试选择微调超参或称稳定效率收益。本轮首先做可解释对照，尚未形成用户自己的新算法。


## 实际完成结果（2026-10-11，以本节为准）

权重官方LFS SHA已核验通过，实际三轮正式SFT完成，耗时638.31秒（含基线/验证/测试生成，非纯训练时间）。413训练、93验证、84测试，验证选择第3轮。基础参数训练前后SHA一致，LoRA非零梯度及参数变化记录在reports/vlm_sft_42.json；rank4/alpha8，409,600可训练参数，基础模型约500M。模型不是1B—3B或更大容量，先以本机可承担规模完成生成式训练链路。

84件测试商品：JSON有效率0.9048→1.0000，类别元数据一致率0.2024→0.4286，颜色0.4524→0.6429，联合0.1071→0.2857；类别宏平均0.2226→0.3375，颜色宏平均0.1843→0.3435。单种子、小样本、非随机覆盖，不称统计显著/人工视觉准确率/推荐收益。25件测试目标类别训练中未见，类别一致率仅0.08；59件已见类别为0.5763。说明分类泛化与标签歧义仍是瓶颈，详细错误输出保存在本机artifacts/hm/vlm-sft-42/error_analysis.json。

Token对照四组实际运行完成：full/uniform32/norm32/uniform16验证联合一致率为0.3011/0.3118/0.3441/0.2688，p50约471.1/461.9/471.7/486.6ms。范数保留没有实际加速，16个token损失质量，未验证稳定收益。计时包含视觉编码和生成，排除图片预处理；固定顺序单次、不同输出长度，无重复统计，不能宣称可靠加速。完整输入的预计算特征生成与全部93条原验证输出一致。报告reports/vlm_token_benchmark.json；报告版本c4f3dee35cc0与最终服务版本不同，仅后续加强数据摘要校验/请求类型检查，适配器相同。

本机生成式API8767已启动，标准64token；推荐API8766独立运行。服务校验基础权重SHA、适配器SHA、数据与提示摘要，错误输入拒绝，并轮转记录时间/请求方法/状态/版本。部署只加载本机已验证文件，不向公网发布。HTTP重载核验见reports/vlm_http_check.json。Token实验结束内存约2.03GB allocated/3.03GB driver，不是峰值；没有生成式接口并发压力或生产SLA测试。

代码功能区分：train_generative_vlm.py仅四步可行性；finetune_vlm_attributes.py为正式训练；vlm_metrics.py为弱标签评测；vlm_serve.py为重载推理；benchmark_vlm_tokens.py为效率对照。后续个人研究可从训练未见类别、属性标签质量、随机顺序重复性能验证入手。尚无用户独立提出验证的原创算法，学习未自动标记完成。
